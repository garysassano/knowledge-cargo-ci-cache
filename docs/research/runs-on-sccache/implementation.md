# Proposed compiler-cache implementation map

Status: Proposed and untested integration work. This page specifies requirements; it does not describe a released RunsOn feature. Use [the research index](README.md) for scope, sequencing, and the [version refresh](baseline.md#release-refresh-2026-09-06).

## Required Upstream Changes

### `sccache`

| Priority | Change                                                                                 | Current location                  | RunsOn value                                              |
| -------- | -------------------------------------------------------------------------------------- | --------------------------------- | --------------------------------------------------------- |
| P0       | Preserve typed backend errors instead of converting every non-404 read error to a miss | `src/cache/cache.rs`              | Fast failover, correct telemetry, and safer auth handling |
| P0       | Track and bound every multilevel write and backfill task                               | `src/cache/multilevel.rs`         | Prevent unfinished writes from disappearing at teardown   |
| P0       | Add explicit `drain` and atomic stop-with-stats operations                             | `src/server.rs`, command protocol | Real post-step durability accounting                      |
| P0       | Make daemon backend identity queryable                                                 | server and command protocol       | Detect stale configuration safely                         |
| P1       | Make lookup deadlines configurable and staged                                          | `src/compiler/compiler.rs`        | Avoid a fixed 60-second failure penalty                   |
| P1       | Add bounded retry, jitter, and circuit-breaking hooks                                  | remote storage path               | Handle transient S3, KMS, proxy, and token failures       |
| P1       | Reuse the lower-tier hit bytes for multilevel backfill                                 | `src/cache/multilevel.rs`         | Remove the second origin fetch                            |
| P1       | Stream or spill remote entries and enforce size limits                                 | `src/cache/cache.rs`, cache I/O   | Bound memory and improve concurrency                      |
| P1       | Support conditional create and integrity metadata                                      | storage trait and backends        | First-writer-wins and poisoning detection                 |
| P1       | Expose backend request latency, bytes, retries, and result classes                     | stats model                       | End-to-end attribution                                    |
| P2       | Make compression level/configuration explicit and versionable                          | cache I/O and config              | Tune cold CPU against remote bytes                        |
| P2       | Strengthen local-cache ownership and recovery metadata                                 | local LRU                         | Safer sticky operation                                    |

Cache write failure should remain separable from compiler correctness, but a strict population command needs a machine-readable result that can fail readiness publication when writes were unsuccessful.

Upgrading an unrelated OpenDAL installation does not change the OpenDAL embedded in a released `sccache` binary. The dependency must be updated in `sccache`, tested, and released.

### RunsOn Action

Implement the transactional setup and post contracts in the action, including:

- Exact binary and checksum policy.
- OIDC admission with broker-specific audience, nonce handling, and separation of signed identity from locally requested mode.
- Trust and namespace resolution from broker policy and independent RunsOn platform attestation.
- Backend validation.
- Stale-daemon control.
- `CARGO_INCREMENTAL=0`.
- Delayed wrapper export.
- JSON stats and redacted summary.
- Stable per-invocation wrapper fallback that never launches a second compiler for an ambiguous in-flight request.
- Gateway session and drain.
- Sticky `sccache` ownership when supported.

### RunsOn Stack And Agent

Implement:

- Reader, writer, overlay, maintenance, and no-cache policies with no ambient instance-profile compiler-cache authority.
- Compiler-cache-specific broker sessions with OIDC claim validation, replay protection, RunsOn instance attestation, run-state checks, and remote leases/fencing.
- Bucket, Access Point, or namespace separation.
- Endpoint and bucket policy controls.
- Gateway deployment, limits, health, and telemetry.
- Sealed-generation index, signed readiness, monotonic pointers, quarantine, and rollback storage.
- Remote replay-admission resources only if a precisely qualified deferred-write durability promise is implemented.
- Sticky-mode ordering, external lineage metadata, remote publication leases/fencing, and crash-consistent snapshot controls.
- CloudWatch or OpenTelemetry metrics and alerts.

CloudFormation is the pinned primary implementation. If RunsOn exposes equivalent Terraform or OpenTofu module settings, mirror the stable CloudFormation contract after the resource and IAM design is validated rather than inventing a divergent interface.

## Open Decisions

| Decision                       | Options                                                                                          | Evidence needed                                                                                |
| ------------------------------ | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| Gateway protocol               | WebDAV prototype, loopback S3, upstream backend                                                  | Pass-through overhead, feature fit, implementation complexity                                  |
| Remote authority               | Brokered STS in local gateway, remote proxy, Access Point credentials                            | Root-threat review, IAM matrix, latency, operational cost                                      |
| Membership index               | Bloom, Xor, sorted shards, DynamoDB, Redis or Valkey                                             | Key count, memory, build time, false-positive impact, consistency                              |
| Write acknowledgement          | Remote commit only, or future remotely admitted deferred replay                                  | Population wall time, stated failure domain, broker envelope, replay authority and operations  |
| Sticky publication             | Remotely fenced designated publisher, read-only or copy-on-write consumers, partitioned lineages | Concurrency pattern, hot-set overlap, snapshot overhead, control-plane publication support     |
| Namespace digest inputs        | Repository, trust, scope, platform, toolchain policy                                             | Collision analysis, policy size, migration needs                                               |
| Compression default            | zstd 1, 3, 6, or 9                                                                               | Paired cold/warm jobs, bytes, CPU, cost                                                        |
| Ordinary PR policy             | Canonical read-only or disabled                                                                  | Threat model, confidentiality, warm value                                                      |
| Strict-mode default            | Fallback or fail                                                                                 | Workflow criticality and population ownership                                                  |
| Retention                      | Current age, longer canonical, shorter overlays                                                  | Reuse-distance distribution and cost                                                           |
| S3 Express writer coordination | Client-supported conditional creation, external reservation if required, or no writer mode       | Exact operation support, duplicate contention, publication fencing, failure recovery, and cost |
| Cost threshold                 | Project-defined currency per saved minute                                                        | Runner and service rates, volume, SLO                                                          |

No open decision should be resolved from hit rate or a transport microbenchmark alone.
