# Compiler-cache research validation

Status: Proposed qualification tests, not completed experiments or released features. This page owns experiment-specific observations, failure injection, and promotion gates. [Measurement procedure](../../operations/measuring-cache-performance.md) owns sampling, accounting, and reporting; [design pages](README.md) own behavioral contracts.

## Experiment setup

Use the [canonical scenario matrix](../../operations/measuring-cache-performance.md#scenario-matrix) and [repetition and stopping rules](../../operations/measuring-cache-performance.md#repetition-and-stopping-rules). In addition to the runner, source, compiler, and workload controls there, hold cache/gateway binary digests, compression, namespace schema, trust mode, Cargo-input choice, and backend encryption/lifecycle constant within each pair. Record the runner-to-storage region/AZ relationship in sanitized form.

Choose implementations and dependencies from the [roadmap](roadmap.md). Change one feature at a time: pass-through, negative cache, membership, coalescing, ephemeral L0, remote writes, and sticky L0 are separate comparisons. Deferred replay follows a proven synchronous writer. Native GHA isolation states use separate cold populations; backend-specific conformance lives in [Alternative backends](alternative-backends.md).

## Performance states

Extend the generic cold, warm, changed-source, invalidation, concurrency, and failure scenarios with these attribution controls:

| Control                                 | Question                                                                                                |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Cache-disabled gateway pass-through     | What does the integration add without any cache value?                                                  |
| Local confirmed miss without remote I/O | What do hashing, daemon, wrapper, and compiler interaction cost?                                        |
| Gateway known-negative                  | What does validated local membership handling cost?                                                     |
| Origin-confirmed 404                    | What does a remote confirmed miss add?                                                                  |
| Empty read-only full workload           | What is the combined miss-path penalty? This does not isolate S3 latency.                               |
| Complete protected population           | What does remotely committed, publication-eligible population cost?                                     |
| Concurrent identical keys               | How much origin fan-out does coalescing avoid?                                                          |
| Weighted production-like mix            | What do realistic warm frequency, source changes, population, and failures imply for job time and cost? |

## Failure and fallback matrix

Each row is an injected test with a recorded expected outcome, detection time, terminal state, and recovery. The [action fallback contract](action-lifecycle.md#fallback-semantics) applies throughout: an ambiguous in-flight compilation never starts a second compiler automatically. Ordinary build results and strict population results are recorded separately.

| Injection                                                                                                            | Required observation and recovery                                                                                                                                                                                                                                                                                     |
| -------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Missing binary, wrong checksum, invalid/unsupported input, or conflicting identity                                   | Setup disables the integration or fails strict mode before compilation. Verify an approved binary/configuration restores service and existing supported inputs remain compatible.                                                                                                                                     |
| OIDC replay, wrong claims, stale run, attestation mismatch, or admission policy overflow                             | Broker denies a session; no cache authority is created. Exercise the full [admission](trust-and-publication.md#writer-session-admission) and [policy](trust-and-publication.md#iam-and-bucket-policy) contracts, including completed/cancelled jobs.                                                                  |
| Stale daemon configuration                                                                                           | Fingerprint mismatch stops or rejects the daemon. Failed restart falls back before the next invocation; stale runtime state cannot be reused.                                                                                                                                                                         |
| Absent or completed-empty readiness                                                                                  | Readers bypass shared caching; only a valid protected population can activate a ready generation.                                                                                                                                                                                                                     |
| 401/403 or KMS denial                                                                                                | Typed authorization failure opens or disables the affected path; it is not reported as an ordinary miss. Recovery requires valid refreshed authority or corrected policy.                                                                                                                                             |
| Origin-confirmed 404                                                                                                 | Normal miss; compilation may write only with the selected authority.                                                                                                                                                                                                                                                  |
| 409/412 with identical or conflicting concurrent writers                                                             | Reconcile by operation type and authoritative stored metadata. Restart uploads where required; conflicting content alerts and quarantines instead of overwriting.                                                                                                                                                     |
| 429/5xx, KMS throttling, DNS/connect/TLS failure, or first-byte/idle/total timeout                                   | Bounded retries, staged deadlines, and circuit behavior reach safe fallback within the declared budget. Record retry cost and recovery after origin repair.                                                                                                                                                           |
| Checksum mismatch, truncated body, invalid metadata, or oversized object                                             | Bounded decoding rejects/quarantines the object and uses direct compilation; maintenance can repair or rotate the affected generation.                                                                                                                                                                                |
| L0 disk/inode full, queue full, or spool corruption                                                                  | Admission remains bounded. Record eviction/bypass/rejection; an unresolved strict population fails without readiness. Validate GC, reset, or origin recovery.                                                                                                                                                         |
| Gateway, daemon, or origin-proxy crash before and during compilation                                                 | Pre-workload failure disables caching; in-flight ambiguity preserves exactly one compiler attempt. Only a later safe invocation can use the direct path.                                                                                                                                                              |
| STS/GitHub token expiry or clock skew                                                                                | New origin work stops when authority expires. Refresh succeeds only for a still-admitted run; closing a local session does not claim immediate STS revocation.                                                                                                                                                        |
| Stale positive index, false-negative bug, corrupt/missing shards, or stale generation                                | Confirmed positives may miss at origin; suspected false negatives disable the index. Invalid metadata falls through to origin and is rebuilt before reuse.                                                                                                                                                            |
| Sticky restore explicitly unavailable, missing contract, invalid mount, or timed out                                 | Assert each [versioned platform state](../../reference/runson-cache-and-disk-details.md#sticky-disk-failure-boundary) separately: terminal unavailability continues cold in v2.3.1; contract, validation, and deadline errors can fail before wrapper fallback. Test the explicit wait setting and deployed behavior. |
| Sticky warning/reset thresholds, reset skipped while in use, or inactive expiry                                      | Inject the [released capacity and lineage conditions](../../reference/runson-cache-and-disk-details.md#sticky-disk-capacity-and-reset). Confirm a bounded cold path, preserved trust separation, and no partial publication.                                                                                          |
| Cancellation, workload failure, timeout, missing post, or interruption during drain/snapshot publication             | Preserve the real job result and previous selected generation/lineage. Unfinished work is visible; only remotely admitted replay may survive lost authority.                                                                                                                                                          |
| Pointer rollback, unexpected predecessor, stale fence, expired lease, duplicate activation, or late completion       | Publication is denied; the previously selected and retained rollback state remains usable.                                                                                                                                                                                                                            |
| Cross-repository/scope access, unauthorized list/read/write/delete, multipart, tagging, ACL, KMS, or role escalation | The [trust matrix](trust-and-publication.md#target-trust-model) denies the wrong principal through every available authority path.                                                                                                                                                                                    |
| Malformed diagnostic input, credentials, signed URLs, or private identifiers in logs                                 | Exported records and summaries pass adversarial redaction checks against the [sanitization contract](../../reference/cache-measurement-schema.md#sanitization).                                                                                                                                                       |

## Contract tests

These assertions complement the failure injections without maintaining a second copy of each design:

| Contract owner                                             | Deterministic proof required                                                                                                                                                                                                                                                                            |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Trust and publication](trust-and-publication.md)          | Approved complete writer dependency graph; exact policy denial matrix; correct namespace/provenance; nonempty declared workload and zero disqualifying writes before readiness; sealed membership and fenced pointer activation; quarantine and rollback. Checksums alone never establish authenticity. |
| [Action lifecycle](action-lifecycle.md#post-transaction)   | Seal producers, wait for active work, disable backfills, fix and drain a watermark, report terminal counts, and release resources within hard deadlines. Prove one compiler launch per invocation and no untracked successful writes.                                                                   |
| [Gateway writes](gateway.md#write-acknowledgement-modes)   | Every initial success is remotely committed and readable by a fresh authorized client with valid length/checksum/key binding. Qualify any later deferred mode against its explicit replay failure domain; idempotent duplicate replay cannot advance readiness twice.                                   |
| [Gateway reads](gateway.md#request-coalescing)             | No stale single-flight entry blocks later requests; cancellation and overload remain bounded; lower-trust bytes never backfill canonical storage; invalid indexes fall through safely.                                                                                                                  |
| [Sticky local tier](sticky-local-tier.md#ownership-marker) | One local owner per volume and one remotely fenced publisher per lineage; data/marker/parent durability, owner shutdown, freeze/unmount, and snapshot-before-pointer ordering. Test schema/trust mismatch, GC, concurrent clones, and cancellation at each transition.                                  |
| [Alternative backends](alternative-backends.md)            | Native GHA finalization and fresh-job visibility; Express session/endpoints/placement and selected write coordination; Redis/Valkey eviction/failover/persistence; disposable-only Memcached semantics.                                                                                                 |

Validate RunsOn infrastructure changes through template checks, policy scans, IAM allow/deny simulation, a reviewed isolated-stack change set, replacement/rollback tests, and cost attribution. Validate this archive through its [maintenance checks](../../operations/maintenance-checklist.md) when recording results.

## Promotion gates

1. Pass every applicable correctness, authorization, durability, fallback, publication, and hard-deadline assertion. A rare deterministic failure blocks promotion regardless of percentiles.
2. Use the predeclared sampling plan to demonstrate a meaningful improvement in weighted complete-job time, with an uncertainty interval supporting the conclusion. Include cold, population, warm, source-change, failure, fallback, timeout, and cancelled jobs.
3. Meet project-specific tail, maximum-duration, resource, and cost budgets. Report tails only when sample precision supports them. Gateway overhead, fan-out reduction, and sticky restore/save cost each need an independently measured budget.
4. Record the implemented versions, sanitized observations, limitations, rollback, and adopted conclusion through [roadmap R1](roadmap.md#qualify-larger-experiments-only-when-needed).

Acceptance budgets are workload-specific choices. Set them before testing; they are not measured properties of these proposals.
